# MySQL错误分类记录

记录方式：运行 `03_mysql_error_demo.py` 实际观察得到，并补充 `test_mysql_errors.py` 的集成测试结果。

## 连接失败

- 异常类：`ConnectionTimeoutError`（继承自 `mysql.connector.Error`）
- errno：2003
- sqlstate：None
- 含义：客户端根本没连上服务器（这里是把端口改成 1 模拟的）。`errno 2003` 是客户端侧的错误编号（"Can't connect to MySQL server"），因为连接还没建立，服务器没机会返回 SQLSTATE，所以 `sqlstate` 为空。

## SQL语法错误

- 异常类：`ProgrammingError`
- errno：1064
- sqlstate：42000
- 含义：连上了服务器，但服务器看不懂这条 SQL。`errno 1064` 是 MySQL 的语法错误编号，`sqlstate 42000` 表示"语法错误或访问规则违例"。这类错误是**程序写错了**，重试也没用。

## 查无记录

- 返回值：None
- 是否抛异常：否
- 含义：查一条不存在的记录是**正常业务结果**，不是数据库异常。所以 `get_task()` 返回 `None`，由调用方决定怎么处理（例如转成 404 或提示用户），数据库层不抛异常。

## 失败事务

- 事务内是否创建：是（事务内能查到，任务ID 49）
- rollback后是否存在：否（再查返回 None）

说明：`start_transaction()` 之后插入的记录，在 `rollback()` 后消失，证明本次插入确实位于该事务中，且回滚生效。

## 汇总对照

| 情况 | 异常类 / 返回值 | errno | sqlstate | 性质 |
|---|---|---|---|---|
| 连接失败 | ConnectionTimeoutError | 2003 | None | 环境问题（客户端侧） |
| SQL 语法错误 | ProgrammingError | 1064 | 42000 | 程序写错 |
| 查无记录 | 返回 None | — | — | 正常业务结果 |
| 事务内出错后回滚 | 插入被撤销 | — | — | 事务保护生效 |
